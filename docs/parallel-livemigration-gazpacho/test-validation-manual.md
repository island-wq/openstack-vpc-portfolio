# 1. Gazpacho 병렬 라이브 마이그레이션 시험·검증 매뉴얼

- 분석 자료: Gazpacho TestCase, 2026-10-02, v1.1 Excel 시험표
- 분석 범위: 환경·시나리오·수행 결과·종합 결과·Epoxy 참고·채널 요약·VM1/VM2 비교의 7개 시트
- 단일 VM 채널 수, 대상 VM 수, Compute 동시 실행 수의 분리 검증 적용

## 1. 시험 목적 및 환경

- LACP 20G 환경의 QEMU 멀티채널 메모리 전송 효과 확인
- VM 메모리 크기와 대상 수 증가에 따른 완료시간·대역폭 변화 확인
- 채널 수 증가의 한계와 반복 수행 변동성 검증

| 항목 | 원본 기록 |
|---|---|
| 노드 구성 | Controller·Compute 혼합 역할의 3노드 구성 |
| 서버·CPU | Dell PowerEdge R750, Intel Xeon Silver 4310 적용 |
| 호스트 메모리 | 노드별 128GB 구성 |
| 네트워크 | LACP 3+4 해시 정책, 10G 링크 2개 기반 20G 구성 |
| 스토리지 | Dell PowerStore 3201T, iSCSI Volume Backend 적용 |
| Gazpacho 환경 | Rocky Linux 10.2, Kernel 6.12.0-211.51.1.el10_2.x86_64 기록 |
| 배포 이미지 | Kolla `2026.1-rocky-10` 기록 |
| 주요 구성요소 | Nova 33.0.3, Neutron 28.0.2.dev38, QEMU 10.1.0 기록 |

- 버전 표기는 첨부 시험 환경 기준이며 설치 패키지의 별도 실환경 조회 부재
- 소스·대상 간 양방향 반복 수행 적용
- VM 32GB·64GB 계열의 CPU 10%, 메모리 50% 기록을 수행 결과 기준으로 사용
- 시나리오의 메모리 60% 및 환경표의 CPU 50% 표기와 실측 조건의 차이 확인 필요

## 2. 설정 항목

| 구분 | 항목 | 원본 시험 설정 |
|---|---|---|
| 동시 이관 | `max_concurrent_live_migrations` | 멀티채널 단독·2대 비교군의 `1` 고정 기록 |
| 멀티채널 | `live_migration_parallel_connections` | 단일 VM 2~128채널, 소형 VM 유효 비교군 1·2·4·8채널 적용 |
| 대역폭 제한 | `live_migration_bandwidth` | `0` 기록 |
| 다운타임 | `live_migration_downtime` | `500`ms 기록 |
| 다운타임 단계 | `live_migration_downtime_steps` | `10` 기록 |
| 단계 지연 | `live_migration_downtime_delay` | `75`초 기록 |
| 자동 수렴 | `live_migration_permit_auto_converge` | `False` 기록 |
| Post-copy | `live_migration_permit_post_copy` | `False` 기록 |
| 완료 제한 | `live_migration_completion_timeout` | `800`초/GiB 기록 |
| 제한 초과 처리 | `live_migration_timeout_action` | `abort` 기록 |

- 멀티채널 설정값과 실제 QEMU 연결 수의 대조 필요
- 설정 파일과 실행 중 서비스의 설정 일치 여부 확인 필요
- 채널별 CPU 소비와 TLS 적용 여부의 별도 관찰 필요: [Nova QEMU 연결 수 설정](https://docs.openstack.org/nova/2026.1/configuration/config.html#libvirt.live_migration_parallel_connections)

### 단일 VM 시험 설정 예시

```ini
[DEFAULT]
max_concurrent_live_migrations = 1

[libvirt]
live_migration_parallel_connections = 16
live_migration_bandwidth = 0
live_migration_downtime = 500
live_migration_downtime_steps = 10
live_migration_downtime_delay = 75
live_migration_permit_auto_converge = false
live_migration_permit_post_copy = false
live_migration_completion_timeout = 800
live_migration_timeout_action = abort
```

- 기존 설정에 병합할 단일 VM 검증 예시이며 운영 확정값의 근거 부재
- Kolla 설정 override 반영 후 재구성·서비스 적용 상태 확인 필요
- 설정 변경 전 원본 백업과 진행 중 이관 작업 확인 필요
- 시험 종료 후 기존 설정 복원 및 VM 상태 재확인 필요

## 3. 시험 매트릭스

| 시험 계열 | VM 구성 | 유효 채널 조건 | 실제 반복 수 |
|---|---|---|---|
| 32GB 단일 VM, 초기 기준 | `c16m32d100` 1대, 10G | 2·4·8·16 | 각 5회 기록 |
| 32GB 단일 VM, LACP | `c16m32d100` 1대, 20G | 2·4·8·16·32·64·128 | 2·4채널 각 5회, 나머지 각 10회 기록 |
| 64GB 단일 VM, LACP | `c32m64d100` 1대, 20G | 2·4·8·16·32·64·128 | 각 10회 기록 |
| 소형 VM, LACP | `c4m8d10` 3대·6대 | 1·2·4·8 | 각 10회 기록 |
| 32GB VM 2대, LACP | `c16m32d100` A·B 2대 | 2·4·8·16·32·64 | 각 10쌍, VM별 20건 기록 |

- 32GB 2채널의 추가 반복 `TC-G-M-11`은 대표 비교군과 별도 집계 적용
- 소형 VM의 16·32·64·128채널은 0초·시작/종료 미입력에 따른 미수행 분류 적용
- Case ID 재사용에 따른 시험 계열·VM 사양·채널·원본 행 위치의 복합 식별 필요

## 4. 시험 수행 절차

1. Nova·QEMU·네트워크·스토리지 구성과 기존 설정의 기록
2. 소스·대상 자원 여유, Volume 접근, 네트워크 연결의 사전 확인
3. 한 번에 하나의 비교 변수 변경과 Compute 설정 반영 확인
4. 동일 소스에 VM 배치 후 부하 안정화 5분 적용
5. CPU·메모리·디스크 부하와 dirty page 생성 조건의 고정 적용
6. 다중 VM 동시성 시험의 요청 시점 통일 및 실행·대기 작업 수 기록
7. VM별 시작·종료 시각, 소요시간, 실제 채널 수, NIC 대역폭 수집
8. Host CPU·메모리·디스크, TCP 재전송·Drop·오류 로그 수집
9. VM 실행 상태, 서비스 Health Check, ping 손실·응답시간의 완료 후 확인
10. 동일 조건 반복 후 평균·최소·최대·표준편차 및 방향별 결과 비교

- 멀티채널 단독 시험의 `max_concurrent=1` 고정 적용
- 동시 이관 시험의 채널 수 고정 및 `max_concurrent` 별도 변경 필요
- 부하 발생 시간·대상 메모리 비율·Iperf 사용 여부의 동일 조건 적용 필요

| 채널 | A+B 합산 평균(초) | 합산 최소~최대(초) | VM별 평균(초) |

| 2 | 159.7 | 53~244 | 79.85 |
| 4 | 78.6 | 57~166 | 39.30 |
| 8 | 72.2 | 58~136 | 36.10 |

| 64 | 63.9 | 61~70 | 31.95 |

- 동일 회차 A·B 소요시간 합산 후 10쌍 평균 적용
- VM별 평균은 A+B 합산 평균의 1/2로 재산출 적용
- 종합 시트의 `max_concurrent_live_migrations=1` 기록 확인
- 대다수 유효 시각의 A 종료 이후 B 시작에 따른 순차 이관 패턴 확인
- 예시: A 97초, B 55초, 작업 간 11초 간격으로 합산 152초·전체 경과 163초 구분
- 실제 작업 묶음 경과시간의 `마지막 종료 시각 - 최초 시작 시각` 기준 별도 산출 필요
- 8채널 첫 회차 A의 종료 시각이 시작보다 앞선 원본 오류에 따른 시각 정정 필요
- 표의 A+B 평균은 소요시간 입력값 기준이며 해당 회차의 경과시간 검증 보류
- VM1 비교표의 2~16채널은 초기 10G, 32·64채널은 LACP 20G 기준 사용 확인
- 서로 다른 네트워크와 VM 수를 혼합한 VM1/VM2 개선율의 동시 처리 효율 일반화 근거 부재

## 8. 집계 및 판정 기준

| 측정값 | 집계 원칙 | 판정 시 확인 항목 |
|---|---|---|
| 완료시간 | 시작 시각 존재·소요시간 양수인 행만 포함 | 평균·최대·변동성의 동시 비교 필요 |
| 2대 VM 시간 | 동일 회차의 유효 A·B 합산 | 합산시간·작업 간격·총 경과시간 구분 필요 |
| 단축률 | `(기준 평균 - 비교 평균) / 기준 평균 × 100` 적용 | 동일 VM 수·네트워크·부하·반복 조건 확인 필요 |
| BW | 원본 단위 Gbps로 통일 | Peak·샘플평균·전체 구간 평균의 구분 필요 |
| 서비스 연속성 | ping·Health Check·다운타임 실측 | 미입력 항목을 정상 또는 0으로 대체하는 근거 부재 |
| 안정성 | 이관 결과·오류·재전송·Drop 수집 | 완료 성공과 무중단·서비스 품질의 별도 판정 필요 |

- 500ms 다운타임 설정만으로 실측 중단 500ms 이하 판정 불가
- 미수행 0초 데이터의 성공·고속 이관 실적으로의 집계 제외 적용
- Gazpacho 종합 결과의 VM 응답시간 공백에 따른 서비스 연속성 추가 검증 필요
- Epoxy 참고 시트의 요약 문구와 성공 건수·서비스 행 간 불일치에 따른 총 성공률 재집계 필요
- Evacuation 참고 결과와 Gazpacho Live Migration 성능의 분리 적용
